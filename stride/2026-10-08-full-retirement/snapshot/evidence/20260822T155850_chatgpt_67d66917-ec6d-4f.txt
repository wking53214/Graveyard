# 6. THE MOST IMPORTANT RULE: FOLLOW ARTIFACTS, NOT NAMES

A repository name is weak evidence.

A file lineage is stronger.

A matching implementation fragment is stronger still.

A commit explicitly saying:

> “salvaged from X”

is extremely strong.

A historical conversation saying:

> “move this from X to Y”

is extremely strong.

Therefore construct lineage in this priority order:

### Tier A — explicit provenance

Examples:

- “copied from”
- “salvaged from”
- “ported from”
- “moved from”
- “renamed from”
- “derived from”
- “forked from”

### Tier B — Git-level continuity

Examples:

- identical file history;
- Git rename detection;
- matching blobs;
- identical commit ancestry;
- file introduced in one repository and subsequently appearing elsewhere.

### Tier C — structural/code similarity

Examples:

- distinctive function names;
- identical algorithms;
- unusual constants;
- matching comments;
- matching class structure;
- unique error strings;
- identical configuration structures.

### Tier D — conceptual similarity

Use only as supporting evidence.

Never elevate conceptual similarity into code lineage without stronger evidence.
