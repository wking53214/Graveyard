1. Executive Summary

PASS 4 materially strengthens the conclusion that the ecosystem is not one continuously designed architecture.

The surviving evidence supports a more complicated history:

1. A real Sentinel/Iceberg operational lineage existed early.
   
   - The "OBSERVE" repository contains a July 3, 2026 commit explicitly titled “Initial Sentinel OS upload.”
   - Minutes later, it records “Migrated Iceburg architecture into Sentinel OS repository.”
   - The later "sentinel_os" repository was created immediately afterward.
   - Subsequent commits document real PostgreSQL/Redis execution, CI, live harness tests, deployment infrastructure, and repeated end-to-end verification.

2. Sentinel subsequently became a source of actual extraction/migration.
   
   - "GSA-815" contains an explicit extraction commit stating that "production_harness.py" was extracted from "sentinel_os".
   - The Sentinel history later explicitly calls "GSA-815" a one-commit downstream extraction and says Sentinel remains the canonical actively maintained home.
   - This is one of the strongest direct historical lineage findings in the corpus.

3. GSA-GATEWAY is demonstrably a later consolidation.
   
   - Its August 19 consolidation commit explicitly identifies SECURE, UZTC, WRAPPER, DGK and EDDP material as source repositories and says the operation was a move-only consolidation performed under William's instructions.
   - This is direct migration evidence, not architectural inference.

4. TIE is not historically recovered.
   
   - The current TIE repository explicitly calls itself a “reconstructed implementation baseline” and states that the original complete TIE repository, exact historical "TIE_PACKAGE", and exact "EvidenceRecord" schema were not recovered.
   - Therefore TIE's conceptual existence is supported by later forensic material, but the existence of an original executable TIE system remains UNKNOWN.
   - The current TIE is definitively not proven to be the historical TIE.

5. GEMS is even more explicit about reconstruction.
   
   - Its reconstruction-status document states that the canonical historical repository, production code, exact APIs, transport, schemas, prompts and deployment details were not recovered.
   - Current implementation choices are explicitly labelled "PROPOSED".
   - Therefore GEMS historical architecture is partially evidenced, but its historical executable implementation is not recovered.

6. HERALD is currently executable but historically unproven.
   
   - The repository was created August 20, 2026.
   - Its current commit history documents versions 0.1.0–0.3.0 and real tests.
   - But the evidence recovered here does not establish a pre-existing HERALD implementation or a historical production consumer.
   - Its own development history still describes the downstream consumer seam as something being constructed and tested in the present repository.

7. CCC is explicitly a current implementation without recovered prior history.
   
   - Its README states: “No ratified CCC document or prior harness history is present in the GitHub repository.”
   - This materially strengthens Pass 3's classification of CCC as a current reconstruction.

8. Triad+42 is strongly established as an advisory current implementation, but historical existence remains unresolved.
   
   - The current repository explicitly states that it is an advisory review harness and that the software itself does not perform the reasoning.
   - No independent historical source predating the current repository was recovered.

9. Conservation Kernel is demonstrably experimental rather than historically established as universal.
   
   - The repository calls itself the first independently testable mechanism for the hypothesis.
   - Its report explicitly classifies several stronger claims as "FALSIFIED" or "UNVERIFIED".
   - It is therefore an experiment, not evidence of an older universal enforcement system.

10. FORTRESS genuinely has multiple variants.
    
    - A direct consolidation commit says one implementation came from Sentinel, two from ARCHIVE, and another from Claude history.
    - The evidence therefore establishes multiple surviving implementations, not one continuously maintained canonical FORTRESS lineage.
    - William's creation of the dedicated FORTRESS repository is also explicitly recorded.

11. STRIDE was deleted, but pieces were salvaged.
    
    - CITADEL records that "prohibited_verbs" was salvaged from STRIDE before its deletion.
    - Sentinel records that the loop-detection half of "governance_loop_guard.py" was salvaged from STRIDE before deletion.
    - The evidence explicitly distinguishes these surviving pieces from the lost whole.

12. The GLCM → KAGGLE story is substantially weaker than software lineage.
    
    - The supplied "GLCM" URL resolves to the current "KAGGLE" repository.
    - But KAGGLE's own provenance states that it was created from a pre-existing "GLCM.txt" artifact and that the artifact was a machine-learning competition working session involving Sobel/LBP/GLCM features and LightGBM, not evidence of the governance software architecture.
    - The repository explicitly says its Git history represents archival date, not development history.
    - This contradicts any interpretation of GLCM/KAGGLE as proven continuity of the governance software system.

Bottom-line judgment

The strongest defensible historical model is:

«An operational Sentinel/Iceberg system existed early, absorbed and shed components, and later became one source among several for extraction and consolidation. Other architectural families were developed, reconstructed, salvaged, or consolidated separately. The present ecosystem is therefore a combination of genuine lineage, migration, salvage, reconstruction, and current experimentation — not a single historically explicit master architecture.»

The cleanest story is not proven.

2. PASS 4 Methodology

PASS 4 applied the following hierarchy:

Primary historical evidence > contemporaneous artifact > Git history > deployment/CI evidence > archival artifact > AI proposal > current implementation > inference.

Repository creation dates were treated only as repository metadata.

README statements were treated as evidence of what the repository currently claims, not automatically as evidence of historical truth.

AI co-authorship was not treated as evidence that the AI originated a decision.

A commit was treated as proof of a commit, not automatically proof of deployment or use.

A successful test was treated as proof of that test's execution, not proof of production deployment.

Absence was reported as:

«not found in the searched corpus»

rather than “never existed.”

30. What Actually Happened?

The surviving evidence does not describe a single architecture that was fully designed first and then implemented.

The evidence instead describes a development ecology.

The earliest strong operational lineage is Sentinel/Iceberg.

That system was real enough to support:

- actual code;
- actual tests;
- PostgreSQL;
- Redis;
- CI;
- API integrations;
- production-shaped harnesses;
- live verification;
- deployment artifacts.

From that lineage, code was later extracted into GSA-815.

Meanwhile, other systems were developed or accumulated elsewhere.

Later, material from multiple repositories was consolidated into GSA-GATEWAY.

ARCHIVE preserved fragments and integration artifacts.

FORTRESS accumulated multiple implementations from Sentinel, ARCHIVE and conversation history.

VANGUARD was extracted from DGK.

STRIDE was deleted, but portions survived in CITADEL and Sentinel.

Then a new reconstruction phase occurred:

- TIE was reconstructed from forensic summaries.
- GEMS was reconstructed from GEMS-FER evidence.
- CCC was implemented from a supplied directive without recovered prior ratified history.
- Triad+42 was implemented as an advisory harness.
- Conservation Kernel was implemented as a testable hypothesis.
- HERALD was implemented as a new interpretation layer.

The present ecosystem therefore combines:

«continuation + extraction + migration + consolidation + salvage + reconstruction + experimentation.»

That is the strongest historical conclusion.
